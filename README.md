浙江大学学生机器人协会 2026 年干事纳新题 · **教学部**作答仓库。

这个仓库用来存放教学部部门工作题（4.5.1 内训选题、4.5.2 幻灯片制作、4.5.3 资料整理）的全部成果，

## 教学材料是怎么组织起来的

先设计讲课逻辑，再做幻灯片，顺序不颠倒：

1. `topic/讲课设计.md` 定下学习地图、三个模块、每个模块的问题链和四次互动，
   并写明每一处简化怎么标注、条件补在哪里；
2. `topic/讲义.md` 先给出概念地图（用数据编程 → 四个关键组件 → 问题类型 → 训练与测试），
   再承接页面上放不下的内容——完整推导、数据来源、条件与边界清单、术语表和练习答案；
3. `slides/` 只放结论、结构、图表和问题（页面易懂），正式定义、适用条件、反例和类比失效边界
   全部写进备注（备注严谨）；
4. `assets/` 里的配图不是手绘示意图，而是对一组合成数据真实执行
   「最小二乘拟合、梯度下降训练、多项式拟合」之后得到的结果。

运行 `python3 assets/make_figures.py` 可以重新生成全部配图与 `pwm_speed.csv`
（需要 `numpy` 与 `matplotlib`），便于以后把合成数据换成真实采集的 PWM 与速度数据。

## 四问回答

### 1. 你在本次任务中使用了哪些 Git 或 GitHub 功能？

- 在 GitHub 上创建远程仓库，并在本地用 `git init` / `git remote add` 建立对应关系；
- 用 `git status`、`git diff` 查看改动，用 `git add`、`git rm` 挑选要提交和要删除的文件；
- 分阶段提交：先提交内训选题，再提交幻灯片与配图，最后完善 README，避免一次性上传全部文件；
- 用 `.gitignore` 排除本地构建目录，保证仓库里只留下有意义的成果文件；
- 新建分支 `docs/readme-checklist` 做小修，通过 Pull Request #1 合并回 `main`，体验了一次协作流程；
- `git push` 推送到远程仓库，并用 `git log --oneline --graph` 检查提交历史。

### 2. 操作过程中遇到了哪些问题？你是如何解决的？

1. **中文文件名在命令行里容易出错。** 路径统一用引号包起来，并在推送后到网页上逐个确认文件名与
   目录结构显示正常。
2. **推送大文件时连接被中断。** 直连 GitHub 时多次出现连接重置，改用本机代理端口后推送成功；
   推送完成后用 `git ls-remote` 与网页端双向确认远程确实收到了内容。
3. **导出的 PDF 里中文全部变成空白。** 原因是转换工具没有加载到中文字体。为转换过程指定了一份
   明确的字体配置后重新导出，中文与代码字体都正常显示，并逐页对照源文件检查了一遍。
4. **中途改过选题。** 最初做的是传统视觉方向，后来决定换成机器学习基础，于是删掉了旧配图和旧课件，
   重新生成了 `assets/` 里的全部图片与 `slides/` 里的两个文件。这件事让我体会到
   `.gitignore` 和分阶段提交的价值：删旧文件、加新文件都只用了两条命令，历史也很清楚。

### 3. 如果将来需要多名教学部成员共同维护这个仓库，你认为应当如何组织文件与修改流程？

**文件组织**：保持「一类资料一个目录」的结构。目前 `topic/` 放课程方案、讲课设计与讲义，
`slides/` 放幻灯片源文件与导出件，`assets/` 放公共图片与生成脚本。以后每次内训单独建一个子目录
（如 `slides/2026-机器学习入门/`），避免不同年份的资料混在一起。文件名统一写成「主题-版本」的形式，
不使用「最终版」「新建文件夹」这类无法辨认的名字。

**修改流程**：`main` 分支保持可读、可展示的状态，任何修改先开分支，改完后提 Pull Request，
由另一名成员看过再合并。提交信息写清楚「改了什么、为什么改」，一次提交只做一件事。

**长期维护**：公共资源（字体、模板、生成脚本）统一放在 `assets/`，避免各人复制多份导致不同步；
课件的源文件与导出件必须成对提交，并在 README 里维护一份资料索引；对不确定是否还要用的内容，
先移到归档目录而不是直接删除。

### 4. 本次纳新题中是否使用了 AI 工具？如果使用，请说明 AI 参与了哪些部分，以及你进行了哪些检查与修改。

**使用的工具**：Codex（AI 编程助手），用于资料整理、方案初稿、配图脚本与幻灯片框架；
转换 PDF 时使用了本机安装的文档转换工具。

**AI 参与的部分**

- 协助把内训选题的想法整理成结构完整的 Markdown 方案、讲课设计与讲义；
- 协助编写 `assets/make_figures.py`，生成幻灯片里用到的散点拟合、误差与 MSE、
  梯度下降轨迹、学习率对比、过拟合对比等六张图，并导出学员用的 `pwm_speed.csv`；
- 协助搭建幻灯片的页面骨架与排版，包括流程图、表格、公式页和互动页；
- 协助整理本 README 的结构。

**我做的检查与修改**

- 逐页对照幻灯片，把不符合自己讲述习惯的表述改回口语化，删掉自己讲不清的内容；
- 核对关键事实：均方误差的定义、梯度下降的更新式、收敛条件 0 < η·c < 2 的推导、
  过拟合与欠拟合的判定，确认幻灯片里出现的每个数字与 `make_figures.py` 的输出一致；
- 重新运行 `make_figures.py`，逐条核对讲义里的「关键数字一览」表，
  确认 MSE = 92.6、曲率 c ≈ 0.745、学习率超过 2.68 会发散这些结论都能复现；
- 把课件里所有没有出现在例子之后的定义都调整成「先例子、后定义」；
- 检查导出 PDF 的每一页，确认没有文字被裁掉、表格没有串行、图片没有被拉伸；
- 确认幻灯片里没有出现我无法在面试中解释的内容。

**第二轮修订改了什么**（针对自查发现的四类问题）：

- 修正讲义里顶点式的系数——`L(w) = L_min + c(w − w*)²` 应为 `L_min + ½c(w − w*)²`
  （c 是二阶导，二次项系数是 c/2），并把 `mean(x²)` 的舍入值从 0.3726 改为 0.3725；
- 互动页问的数和答案页演示的数原本对不上（问 8.0、答 3.20），改成问 3.2、答 3.2，
  同时把 8.0 的结果写进备注和讲义作为追问；
- 补上归一化这一步：讲义第一次出现 w ≈ 200 时，同时给出 x = (PWM − 1500) / 500
  和 b 的固定值，说明它和第 10 页的 w ≈ 0.398 是同一个参数在不同输入刻度下的取值；
- 补齐结构：新增一页模块三小结、把第 6 页「四样缺一不可」补全为四样、
  把第 14 页发散图的纵轴改为对数刻度（原来发散的点飞出了画面，看不出问题），
  并按「页面易懂、备注严谨」把正式定义、适用条件、反例和类比失效边界补进备注与讲义。

**第三轮修订改了什么**（调整课程定位）：

- 参考《动手学深度学习》（PyTorch 第二版）第 1 章「引言」的框架，
  把 15 分钟微课从「一个模型怎么被训练出来」调整为**概念入门**：
  用数据编程 → 四个关键组件（数据、模型、目标函数、优化算法）→ 问题类型（监督 / 无监督 / 强化）→
  训练与测试、过拟合；
- 课程从 21 页变为 22 页：新增「用数据编程」「四个关键组件」「监督学习：回归与分类」
  「无监督与强化学习」「任务类型判断」等内容，删去学习率数值实验等偏调参的页面；
- 梯度下降的推导、收敛条件、归一化、精确率与召回率的计算全部下移到讲义，
  课堂上只保留「它在做什么」的直觉，保证 15 分钟讲得完、听得懂；
- 讲义新增第一节「概念地图」和三条概念练习题，术语表补上无监督 / 强化学习、
  模型族、表示学习、端到端训练等词条。

**AI 没有参与的部分**：选题的方向与取舍、听众基础的判断、三课时的时长分配、互动问题的设计取舍、
失效清单的增删，以及最终提交与否的决定。
