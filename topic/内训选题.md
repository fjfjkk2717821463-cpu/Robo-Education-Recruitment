## 一、课程名称与主要内容

**课程名称：机器学习基础——让程序自己从数据里找规律**

这门课不碰深度学习框架，也不做公式推导，只把机器学习最核心的一条链走完：
**数据 → 模型 → 目标函数 → 优化 → 泛化**。前两节课重在「这门技术在做什么」的入门理解，
第三节课再回到「怎么判断它真的能用」。

整门课用两台小车的真实问题贯穿：一个是「给电机一个 PWM 指令，小车实际跑多快」的**标定问题**，
另一个是「左右两个传感器读数，该往哪转」的**判断问题**。学员结课时能自己用 numpy 写出梯度下降，
看着损失曲线一步步下降，并说清楚为什么有些模型训练时很准、装到车上却不行。

主要内容分八块：

1. **机器学习在做什么**：规则写不出来的时候，为什么可以反过来用数据定参数（用数据编程）；
2. **四个关键组件**：数据、模型、目标函数、优化算法；
3. **问题类型**：监督学习（回归与分类）、无监督学习、强化学习分别在什么情况下用；
4. **数据**：样本、特征、标签，以及数据的两个坑（垃圾进垃圾出、数据不具代表性）；
5. **模型**：一个带参数的函数，例如 ŷ = w·x + b；
6. **目标函数**：把「差多少」变成一个可以比较的数（均方误差）；
7. **训练**：梯度下降与学习率；
8. **泛化与评价**：训练集 / 验证集 / 测试集，过拟合与欠拟合；为什么准确率会骗人，
   召回率与精确率各在说什么。

## 二、课程面向的对象及所需基础

- **面向对象**：机协大一、大二成员。尤其适合写过一点 Python、但对「AI 到底怎么学会的」
  只有模糊印象的同学；也适合想补上机器学习基础的高年级成员。
- **需要的基础**：Python 基础（变量、列表、循环、函数）；看得懂二维坐标图；会用命令行运行脚本。
- **不要求**：微积分、线性代数、概率论的正式训练；不需要 GPU；不需要学过任何算法。
- **课程取舍**：全程用 numpy 手写，不依赖深度学习框架，保证每一行代码都能被解释和复现。
  导数与矩阵只用到「斜率」和「往低处走」的直觉，完整推导放在讲义里供有兴趣的同学课后看。

## 三、希望参与者获得的知识与能力

**知识层面**

- 能用自己的话说清「用数据编程」和传统编程的区别，并说出机器学习的四个关键组件；
- 能说清样本、特征、标签分别指什么；能判断一个任务是监督、无监督还是强化学习，
  并说出监督学习里回归与分类的区别（详见讲义第一节「概念地图」）；
- 理解模型就是一个带参数的函数，「训练」就是在选这些参数；
- 理解损失函数的作用：把模型的好坏压缩成一个可以比较的数；
- 理解梯度下降的直觉——沿着损失变小的方向一步步走，而不是一步求出最优解；
- 理解学习率对训练的影响，能说出过大和过小分别会发生什么；
- 理解泛化、过拟合与欠拟合，能看懂训练误差与验证误差两条曲线的分歧；
- 理解准确率在类别不平衡时为什么会误导人，召回率与精确率各在说什么。

**能力层面**

- 能用 numpy 读入一组数据、计算损失、手写一次梯度下降；
- 能画出损失随迭代次数变化的曲线，并据此判断训练是否正常；
- 会按合理的方式划分训练集与验证集，而不只是随机打散；
- 能用「这条规律换一个场地还成立吗」来检查一个模型能不能真的上车；
- 能主动记录并解释至少 3 种训练失效的现象。

## 五、课程的教学形式与实践环节

采用「先看现象、再补原理、现场改参数、最后复盘」的节奏。**定义一律出现在例子之后**，
每节课按同一套问题链推进：为什么需要它 → 它是什么 → 怎么用 → 容易错在哪 → 和旧知识什么关系。

每节课都有四段固定结构：

1. **演示（约 10 分钟）**：先让一条曲线或一个结果跑出来，让学员看到这节课要解决什么；
2. **一起写（约 20 分钟）**：现场敲最小可运行代码，逐行解释每个变量的含义；
3. **自己调（约 15 分钟）**：学员改学习率、改多项式次数、改阈值，观察结果怎么变；
4. **复盘（约 15 分钟）**：把观察到的失败现象写进「失效清单」，讨论原因和对策。

每 5–10 分钟安排一次学生动作（投票、预测、找错），问题只写在幻灯片上，答案由讲者口头给出。
这门课特意把「调参 → 结果变坏」设为常规环节：机器学习里绝大多数时间不是在写代码，
而是在判断「现在这个结果说明什么问题」。

## 六、三个课时的具体安排

### 第 1 课时：数据、模型与目标函数

**核心观点**：机器学习就是把「数据、模型、目标函数、优化算法」串成一条链，四样缺一不可。

**问题链**

1. 为什么需要它：有些问题的判断规则写不出来，但例子有一大堆；
2. 它是什么：监督学习 = 给「输入 + 正确答案」，让程序自己反推规律；
3. 怎么用：把这件事拆成四样东西；
4. 容易错在哪：数据太少、标签记错、拿训练数据给自己打分；
5. 挂回旧知识：和「用一条直线拟合散点」是同一件事。

**内容**

- 先给概念地图：机器学习不写规则，而是用数据把参数定下来（用数据编程）；
  四个关键组件是数据、模型、目标函数、优化算法，后面所有内容都是这四样的展开；
- 对比两种解决问题的方式：传统编程是人写规则，机器学习是从「数据 + 答案」里反推规律；
- 讲清样本、特征、标签：一行数据是一个样本，输入叫特征，要预测的目标叫标签；
- 引入线性模型：预测速度 = w × 指令 + b，w 和 b 是还不知道的数；
- 引入目标函数（这里取均方误差这一种），把每个样本的误差平方后取平均：

$$
L=\frac{1}{N}\sum_{i=1}^{N}\left(\hat{y}_i-y_i\right)^2
$$

**实践**：读入 PWM 与速度数据，画出散点图；给两组不同的 w、b，比较哪一组的 MSE 更小。

**互动点（约在 20 分钟处）**：投票——A 组参数的 MSE 比 B 组大还是小？检查学生是否理解
「损失是一个可以比较大小的数」。

**失效清单**

- 数据本身有错，标签记错或单位混用；
- 特征和标签其实没有关系，把巧合当成了规律；
- 用同一批数据既训练又评估，结果一定偏乐观。

### 第 2 课时：训练与泛化

**核心观点**：学习就是沿着损失下降的方向，一步步调整参数。

**问题链**

1. 为什么需要它：知道了四样东西，还不知道「学」这个动作具体怎么发生；
2. 它是什么：模型是一组待定的参数，损失是一个数；
3. 怎么用：站在损失曲线上朝低处走一小步，反复走；
4. 容易错在哪：步长太大越跳越远，步长太小半天不动；
5. 挂回旧知识：和「下山找最低点」是同一件事。

**内容**

- 梯度下降的直觉：站在损失曲线上，朝下坡方向走一小步；
- 更新式：

$$
w\leftarrow w-\eta\frac{\partial L}{\partial w}
$$

其中 η 是学习率，决定每一步走多大；课堂上不推导偏导，只解释符号的含义；
- 学习率实验：η 太小收敛很慢，η 合适几步到位，η 太大会在最低点两侧来回跳甚至发散；
- 为什么要留出验证集：训练集上的表现只说明「背得熟不熟」，验证集才反映「会不会做新题」；
- 过拟合与欠拟合：两个误差一起大是欠拟合，训练误差小但验证误差大是过拟合。

**实践**：用 numpy 手写梯度下降，把损失随迭代次数的曲线画出来；换三组学习率对比；
再用 1 次、3 次、9 次多项式拟合同一组数据，观察过拟合的样子。

**互动点（约在 35 分钟处）**：预测——学习率调大十倍，损失会怎么变？先让学员说出来再演示。
检查学生是否理解步长对训练的作用。

**失效清单**

- 学习率太大，损失震荡甚至变成 nan；
- 特征没有归一化，梯度下降几乎不动；
- 训练误差一直在降，验证误差已经开始上升；
- 模型复杂度和数据量不匹配，样本太少时更容易过拟合。

### 第 3 课时：评价与上车

**核心观点**：训练指标好看，不等于学到了能用的规律。

**问题链**

1. 为什么需要它：训练时损失明明很小，装到车上却完全不行；
2. 它是什么：训练集 / 验证集 / 测试集的分工，以及过拟合与欠拟合；
3. 怎么用：盯着训练误差和验证误差，看它们什么时候开始分岔；
4. 容易错在哪：准确率 95% 的模型，可能一个该抓住的时刻都没抓住；
5. 挂回旧知识：课后题做得好，不代表期末卷考得好。

**内容**

- 三种数据集的分工，以及为什么不能用训练数据评估自己；
- 用一个具体例子说明评价指标：1000 个样本里 950 个不需要转向，只有 50 个需要；
  一个永远输出「不需要转向」的模型准确率有 95%，但召回率是 0；
- 讲清召回率（该抓的抓住了多少）与精确率（报出的有多少是真的）；
- 阈值 0.5 只是习惯，实际要看漏报和误报哪一种代价更大；
- 回到机器人：现场数据分布和训练数据不一致，是最常见也最致命的失败。

**实践**：用左右两个传感器读数训练一个线性分类器，画出决策边界，统计准确率；
再人为调整阈值，观察漏报与误报怎么此消彼长。

**互动点（约在 50 分钟处）**：找错——这个准确率 95% 的模型，问题出在哪里？
检查学生是否理解准确率在类别不平衡时会骗人。

**失效清单**

- 类别不平衡时只看准确率，会得出完全错误的结论；
- 决策边界被个别离群点拉偏；
- 训练数据来自实验室，现场数据来自赛场，两者不是一个分布。

## 七、课程实施中可能遇到的问题及解决办法

1. **学员数学基础差异大**
   全程只讲直觉和几何图像，不讲微积分推导；用「往低处走」解释梯度，用「每步走多远」解释学习率。
   完整推导放在讲义里，感兴趣的同学课后自己看。

2. **numpy 的维度与广播报错很难懂**
   提前准备最小可运行代码和常见报错对照表（形状不匹配、把列表当数组用、忘记加括号等），
   并把「打印形状」写进示例代码的第一步。

3. **数据是合成的，学完没有实感**
   讲义里写清了合成数据的生成方式和它的局限；有条件就现场用小车跑一趟，用卷尺和秒表量速，
   让学员看到自己采的数据也有噪声和异常点。

4. **有学员已经用过 scikit-learn 或 PyTorch，觉得手写太慢**
   分层任务：基础组先把梯度下降跑通；进阶组用 scikit-learn 复现同一组结果，
   对比两者的损失曲线，并解释为什么框架给出的结果和手写的一致。

5. **环境安装失败**
   提前发一键安装说明（讲义第八节）与常见报错对照，课前先用 5 分钟统一排查；
   必要时提供在线运行方式兜底。

6. **课时超时**
   第 3 课时把评价部分压缩为「指出准确率的问题 + 画出决策边界」，不展开完整的评价指标推导，
   把精确率与召回率的计算留作课后拓展。

## 八、课程完成标准

学员完成三节课后，应当能够独立做到：

- 用 numpy 手写一元线性回归的梯度下降，并画出损失曲线；
- 解释学习率过大和过小分别会发生什么现象；
- 通过训练误差与验证误差的变化判断是否过拟合；
- 训练一个线性分类器并画出决策边界；
- 说出至少两种「只看准确率会得出错误结论」的情形；
- 提交一份包含代码、损失曲线截图和至少 3 条失效记录的 README。
